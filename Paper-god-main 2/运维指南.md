## 🎯 架构关键原理

### Docker网络原理
- **统一网络**: 所有容器必须在同一`veritex-network`中
- **容器通信**: 通过容器名进行DNS解析
- **网络隔离**: 不同网络的容器无法通信（常见故障原因）

### 架构兼容性
- **本地开发**: Apple Silicon Mac (ARM64)
- **生产服务器**: Linux AMD64
- **关键问题**: ARM64镜像无法在AMD64运行 (`exec format error`)
- **解决方案**: 必须使用 `--platform linux/amd64`

### 代理系统原理
- **SakuraCat**: 提供Trojan协议节点
- **Xray**: 本地代理客户端，协议转换
- **环境变量**: HTTP_PROXY/HTTPS_PROXY控制流量路由
- **智能路由**: NO_PROXY避免内部通信走代理

## 🚨 故障排查指南

### 常见问题和解决方案

#### 1. "服务器网关错误" - 前端无法连接后端
**症状**: 前端显示"服务器网关错误，请稍后重试"
**原因**: 前端和后端容器不在同一Docker网络
**解决方案**:
```bash
# 检查容器网络
docker inspect veritex-frontend | grep -A 5 "NetworkMode"
docker inspect veritex-backend | grep -A 5 "NetworkMode"

# 将所有容器加入统一网络
docker network connect veritex-network veritex-frontend
docker network connect veritex-network veritex-backend
docker network connect veritex-network veritex-caddy

# 重启服务
docker restart veritex-caddy veritex-frontend veritex-backend
```

#### 2. 容器状态显示 "(unhealthy)"
**症状**: `docker ps` 显示容器为 unhealthy 状态
**原因**: 健康检查配置错误或应用启动失败
**解决方案**:
```bash
# 检查健康检查配置
docker inspect veritex-backend | grep -A 10 "Healthcheck"

# 检查应用日志
docker logs veritex-backend --tail=50

# 手动测试健康检查
docker exec veritex-backend curl -f http://localhost:8000/ || echo "健康检查失败"

# 重新创建容器（去掉或修正健康检查）
docker stop veritex-backend && docker rm veritex-backend
# 使用正确的启动命令重新创建
```

#### 3. 架构兼容性错误 (`exec format error`)
**症状**: 容器无法启动，显示 `exec format error`
**原因**: ARM64镜像无法在AMD64服务器运行
**解决方案**:
```bash
# 重新构建AMD64镜像
docker build --platform linux/amd64 -f Dockerfile.backend -t veritex-backend-amd64 .

# 或在部署时指定平台
docker run --platform linux/amd64 -d --name veritex-backend ...
```

#### 4. Google Scholar访问失败
**症状**: 后端无法访问Google Scholar
**原因**: 代理配置错误或节点失效
**解决方案**:
```bash
# 1. 测试代理服务
curl -x http://127.0.0.1:8118 -s http://httpbin.org/ip

# 2. 检查代理环境变量
docker exec veritex-backend env | grep PROXY

# 3. 运行节点测试选择新节点
./test-sakura-nodes.sh

# 4. 更新Xray配置并重启
vim /opt/xray/config.json
docker restart xray-proxy
```

#### 5. SSL证书问题
**症状**: HTTPS访问失败
**解决方案**:
```bash
# 检查证书状态
docker logs veritex-caddy | grep -i certificate

# 检查证书有效期
openssl s_client -servername veritex.cc -connect veritex.cc:443 2>/dev/null | openssl x509 -noout -dates

# 强制重新申请证书
docker restart veritex-caddy
```
